These are the labels that tell your self-hosted setup where to connect and which secrets to use.

## What this means in practice

Memory Crystal uses several environment variables across the backend, MCP layers, and plugin/install flows.

## Most important variables

### API keys

- `GEMINI_API_KEY` — Google Gemini API key for Gemini-backed embeddings
- `OPENROUTER_API_KEY` — optional key for durable memory extraction and unified provider routing
- `MEMORY_CRYSTAL_API_KEY` — preferred client-facing API key variable for MCP clients

### Channel visibility

- `RECALL_WORK_CHANNEL_LABELS` — comma-separated bare labels that classify as work channels for unscoped message surfaces. Defaults to empty (all bare labels classify as private). Set during initial deployment and reviewed by the operator before going live.

Unscoped reads have bounded depth: the public `getRecentMessages` query reads one page of at most 200 rows; unscoped recent scans at most 1,000 rows in pages of 200; unscoped search reads at most 200 text rows plus 200 recent rows, in separate transactions. Rows beyond these bounds are not reachable without a `channel` or `sessionKey` on surfaces that support it. Wake reads one channel; pass `channel` to scope it.

## Backend URLs

- `CONVEX_URL` — Convex deployment URL
- `MEMORY_CRYSTAL_API_URL` — preferred client-facing backend base URL for MCP clients

Use `MEMORY_CRYSTAL_*` names for client setup and provider-specific names for backend provider keys.

## MCP / local runtime

- `CRYSTAL_MCP_MODE`
- `CRYSTAL_MCP_HOST`
- `CRYSTAL_MCP_PORT`

## Embeddings / provider selection

- `EMBEDDING_PROVIDER` — currently important for backend behavior
- `GEMINI_EMBEDDING_MODEL`

## Local content / storage

- `OBSIDIAN_VAULT_PATH`

## Example

From `.env.example`:

```env
CONVEX_URL=https://convex.memorycrystal.ai
GEMINI_API_KEY=
OPENROUTER_API_KEY=
GEMINI_EMBEDDING_MODEL=gemini-embedding-2-preview
OBSIDIAN_VAULT_PATH=/path/to/your/obsidian/vault
CRYSTAL_MCP_MODE=stdio
CRYSTAL_MCP_HOST=127.0.0.1
CRYSTAL_MCP_PORT=8788
EMBEDDING_PROVIDER=gemini
MEMORY_CRYSTAL_API_KEY=
MEMORY_CRYSTAL_API_URL=https://convex.memorycrystal.ai
```

## How it actually works

Different variables matter to different layers:

- backend/runtime
- MCP client/server setup
- plugin installation and local health checks

For local command-launched MCP, use `CRYSTAL_MCP_MODE=stdio`.
Use `CRYSTAL_MCP_MODE=http` only when you explicitly want the deprecated local network MCP listener.

## Commands / examples

Example check:

```bash
npm run crystal:doctor
```

## Doctor script behavior

The repo's doctor/smoke checks read these variables and will fail or warn when key values are missing.

For example, with `EMBEDDING_PROVIDER=gemini`, backend semantic recall expects a valid `GEMINI_API_KEY`. OpenClaw plugins and MCP clients should not need a Gemini key; they authenticate to Memory Crystal with `MEMORY_CRYSTAL_API_KEY`.


## Recall cost breaker

The following cost-breaker variables govern per-tenant and global usage limits. See [the configuration environment variables page](/configuration/environment-variables) for full defaults, the envelope, and semantics.

- `MC_COST_BREAKER_ENABLED` — set to `"0"` to disable the breaker.
- `MC_COST_BREAKER_USER_WARN_VECTOR_BYTES`
- `MC_COST_BREAKER_USER_EMERGENCY_VECTOR_BYTES`
- `MC_COST_BREAKER_USER_WARN_TEXT_BYTES`
- `MC_COST_BREAKER_USER_EMERGENCY_TEXT_BYTES`
- `MC_COST_BREAKER_GLOBAL_WARN_VECTOR_BYTES`
- `MC_COST_BREAKER_GLOBAL_EMERGENCY_VECTOR_BYTES`
- `MC_COST_BREAKER_GLOBAL_WARN_TEXT_BYTES`
- `MC_COST_BREAKER_GLOBAL_EMERGENCY_TEXT_BYTES`
