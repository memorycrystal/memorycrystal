## Unreleased

- Project-scoped message recall scans at most 100 visible rows and reads at most 200 rows per sub-lane (text and recent); such a recall reports `messageScan.cap: 100`. Unscoped, channel-only and session-only requests are unchanged. The cost: same-project messages outside the 100 most recent and the 100 most relevant visible rows account-wide are not returned, until a project index exists. Limitation (1) of the ILL-311 entry applies to project-scoped requests with a 100-row margin and a 100-row visible cap, so a caller who writes up to 100 rows of its own can read the count exactly. (ILL-396)
- Recall's recent-memory lane now drops memories from another project before its 50-row cut when the request names a project, so they no longer take slots from same-project memories; they were already removed later in recall, when the lexical lane checked each recent row's project. That check therefore no longer counts those rows toward the cross-project suppression diagnostic; cross-project rows returned by text or vector search are still counted when they are dropped. The hosted MCP package no longer imports the SDK-internal `zod-json-schema-compat` path directly (the SDK still loads it internally), and its `crystal_empty_knowledge_base` annotations come from the shared contract. When the hosted server cannot bind its port, it now names the host, port and error on stderr and exits non-zero, instead of reporting that it is listening. The recall benchmark now covers unscoped, other-peer and other-session messages and checks the session on channel-plus-session requests. `crystal_remember` docs describe `relatedExisting`, and the embedding-retry, re-embed and deploy-gate docs are corrected. Recorded defaults (docs/operations/ILL-397-decisions.md): recalled message text keeps injection markers, the backend name and description length guards move to a separate issue, over-long identifiers stay fail-closed, and non-Latin stop words are documented only. (ILL-397)
- Convex diagnostic logs hash user, actor, channel, session, and extraction-window labels. Every caught error passed to a `console.*` call, including rejected `Promise.allSettled` results, goes through `logError`, which redacts email addresses and current or embedded user identifiers (including those in error data serialized as JSON text) and keeps the first 2,000 characters of each string. It redacts only as much of a long string as the kept part needs, with a margin that keeps an identifier or address crossing the cut out of the kept text; its email matcher bounds the local part to 64 and the domain to 253 characters, and an error it cannot read is logged as a fixed `unloggable error`. OpenRouter backfill logs record status and the fixed reason `provider_error`, not response text. Email log rows retain SendGrid status and the first provider error code or message after the same redaction, capped at 200 characters. Recall punctuation stripping and capture-wrapper removal scale linearly; thrown embedding failures report `retry_unscheduled` when scheduling failed before the final attempt, while final-attempt outcomes are unchanged. Stdio preserves an omitted checkpoint mode so its request body matches hosted, and refuses a null mode as hosted does; checkpoint fields, knowledge-base name errors, and Unicode content limits retain parity. (ILL-395)
- Added a read-only operator probe for default message-lane recall latency, with burst, paced and quiet schedules, optional fixture-scoped calls and an alternating scope comparison; stdout and private evidence expose scope labels while keeping fixture scope values private. (ILL-396)
- Linearized the memory write content scanner, structured-content role formatter, recall compression capital and front-matter detection, model-output fence removal, and OpenClaw prompt-injection tag and line filters without cutting their input or changing their output. Recall now keeps the first 128 distinct informative terms in query order: later terms do not contribute to lexical coverage or the informative phrase; identifiers are still extracted from the full query. Parsed terms are matched literally at word boundaries, so an oversized individual word cannot exceed the regular-expression compiler limit. Ordinary queries are unchanged. Plugin and checksum tests now run in CI; repository plugin copy only, no release. (ILL-392)
- Memories record the agent stamp known at creation. Capture writes an explicit or declared agent id (the plugin's resolved agent, or the stdio server's `MEMORY_CRYSTAL_AGENT_ID` / `CRYSTAL_AGENT_ID`, never a channel prefix). Extraction writes a stamp only when every source message carries the same label, stored from the first source in source-message order. Exact duplicates, near-dedupe, and LTM hygiene merge only rows with the same stamp. Update and supersede never add, change, or remove a stamp: a stamped row keeps its stored label, an unstamped row drops an `agentId` key, and non-object metadata on a stamped row is refused. A supersede successor copies the predecessor's stamp and does not write the request agent id. Hosted `crystal_remember` still forwards only an explicit `agentId`. Existing rows are not backfilled. (ILL-394)
- The recall regression deploy gate now makes ten alternating warm-up calls before the requested measured calls. Warm-up calls count for functional failures but have separate latency reporting; known-source latency calls retain their fixture scope with the message lane disabled, which remains covered by the known-source smoke. (ILL-393)
- Restore full-path coverage in the recall deploy gate: half of its calls are now generic non-identifier queries (unscoped, message lane off) that must report an embed or vector stage, with their own warm p90 limit of 4,000 ms (the call count must be 4 to 100, and at least twice the main cases minus one, so every main case runs); add `docs/operations/recall-switches.md` for the three recall switches; clarify JWT message-control validation and by-id visibility documentation. (ILL-393)
- Added a read-only, single-account operator report of agent stamps, shared markers, recent coverage, and projected agent-scope visibility, with counts and hashed labels (rows without a channel fall in the bare `none` bucket; `none` and `__proto__` are reserved and cannot be allowlisted). (ILL-391)
- Capped and linearized the remaining quadratic regular expressions on request strings. (1) The recall diagnostics label for `channel` and `sessionKey` (`diagnostics.scope`) is cut to its first 512 code points before the path-stripping regular expression runs: that expression rescanned a long run from every start position (a 100,000-character channel cost several seconds of Convex time per recall, so any API key could hold a function for minutes with a megabyte-sized value). The label of any input of up to 512 characters is byte-identical to before; the channel and session key the visibility rules see are untouched. (2) The query URL pattern (it keeps PR numbers and ticket ids out of URLs and extracts URL identifiers, from the query and from candidate memory text) now runs per whitespace-delimited token and skips tokens longer than 2,048 characters; a dash- or dot-joined token of 100,000 characters took 2 to 8 s (quadratic), and the cost is now linear (about 5 microseconds per character on the worst shape, many 2,000-character dotted tokens: 1,000,000 characters take about 5 s; a single long token is skipped). Documented difference: a URL of more than 2,048 characters is no longer recognized as a URL (it stays in the text the PR and ticket expressions see, and is not returned among the query's URL identifiers); every shorter case is unchanged. (3) The OpenClaw plugin's `redactSensitiveContent` and `sanitizeErrorMessage` match the separator after `key`, `token`, `secret`, `password` or `bearer` with one whitespace run (the doubled run was quadratic on a long whitespace tail) and bound the email local part to 64 and the domain to 255 characters (an address with a longer local part is not recognized by the email-then-password pattern); the plugin copy changes in the repository only (no plugin release) and `plugin/checksums.txt` is regenerated. (ILL-390)
- Fixed super-linear secret redaction. The key-name patterns (`SECRET_KEY_NAME`) had unbounded `[A-Za-z0-9_-]*` runs nested on both sides of a keyword, tried at every start position: cubic in the input length (8,000 characters of repeated `token-` stalled a recall for about 20 seconds). The JWT pattern restarted at every `eyJ` that followed a dash and rescanned the whole run (quadratic: 100,000 characters of repeated `eyJ-` took about 1 to 2 seconds, 400,000 about 15). The key-name runs are now bounded to 64 characters on each side of the keyword (inside the `token...count` exclusion too) and the JWT pattern only starts at the beginning of a token run (a lookbehind on the base64url characters; there is no header-length limit), so redaction scales linearly: about a quarter to half a second for 100,000 characters and a few seconds for a million, on one core. Output is identical on realistic text. Documented differences: a key name with more than 64 characters on one side of its keyword is not recognized by the key-name patterns (the Bearer, `sk-`, GitHub and JWT token-shape patterns still apply); a JWT glued directly after a dash (`name-eyJ...`) is no longer matched by the JWT pattern (it is still matched after a space, quote, `=`, `:` or at the start); and a name whose `token` starts more than 64 characters in is no longer excluded by the `token...count` rule (it is redacted: the privacy-safe direction). Applied to the Convex module, the shared MCP contract (both servers), the stdio sanitizer and both plugin copies (repository only: no plugin release); `plugin/checksums.txt` regenerated. (ILL-389)
- A decisive identifier query (a PR number, an allowlisted ticket or a full SHA) that the lexical lane can answer now returns without waiting for the query embedding and the conversation-memory vector search, setting `retrieval.earlyReturn: true` in the response. The `RECALL_IDENTIFIER_EARLY_RETURN` switch controls this behavior: it is on by default and `0`, `false`, `off` or `no` (any case) turns it off with no redeploy; a decisive memory listed in `recentMemoryIds` does not early-return. Results for non-identifier queries are unchanged. (ILL-312)
- Both MCP servers expose recall's bounded message lane through one shared contract: callers can set `messageLimit`, `turnId`, and `excludeRecentMessagesMs`, and receive consistently trimmed, redacted `messageMatches` with the backend's retrieval counts. The hosted server preserves every returned match instead of applying a second three-message cap. The message lane requires API-key authentication; the stdio JWT `crystal/recall:recallMemories` path validates and ignores these controls and does not return `messageMatches` or `retrieval`. (ILL-386)
- Added `crystal_get_memory` to both MCP servers to fetch the full text of a visible memory after `crystal_recall` flags a result as truncated. The existing `/api/mcp/memory` route now returns the same resolved text as recall when compact recall is off; with the production default on, its text is unchanged. Channel and knowledge-base gating match recall exactly, so a memory the caller may not see is reported as not found; project filtering, archived state and empty-text rows are not applied by ID. The response adds no fields. (ILL-385)
- Recall memories keep today's channel rules unless `RECALL_WORK_CHANNEL_VISIBILITY` is turned on. The flag defaults off. With it on, an unscoped recall also returns work-channel memories, and a work-channel recall also returns global memories and same-project work memories, ranked just below an exact channel match when relevance is equal. Memory project matching uses the shared project-identity matcher. The by-id endpoints (read, update, supersede, forget, trace) share the channel and flag semantics, including widened work and global access when enabled; they do not apply recall's project filter, archived-state filter or empty-text filter. A private memory is never reachable. The deeper reads behind filter pressure are opt-in (`RECALL_FILTER_REFILL=on`, default off): with it on, the memory vector lane retries once at 256 hits when filters dropped more than half the window, and each lexical index reads further (up to 256 hits) only when the checks applied to the first window before ranking (visibility, project, store, category and tag filters, the cross-session filter, the identifier-conflict exclusion and rows without usable content) removed more than half of its unique ids. They are optional refills: if a deeper page, a lookup or the retry fails, the recall keeps the first window and reports a degradation. They are off by default because the first production measurement showed they read two to four times as many documents and added several seconds per recall on an account whose memories carry large inline vectors; with the switch unset both lanes read one window, as before. Lexical recall starts at today’s per-index depth, evaluates pressure once over unique ids after pre-ranking filters, and hydrates only new ids in bounded batches without embeddings. (ILL-387)
- Fixed a regression from the message-lane release: when the recent-message lane needed more than one page, its second page failed with an invalid-cursor error (the default 14-day window was recomputed from the clock on every page), so the lane was reported as degraded and its messages were dropped. The window is now fixed once per request. (ILL-311)
- `crystal_recall` no longer returns private-channel messages to unscoped requests. Message recall filters system rows, title generators, notifications and the caller's own just-sent prompt (these hygiene patterns match only at the start of a message, so ordinary conversation about cron jobs, titles or background tasks stays), and uses the five-rule project match for message metadata. `score` retains its lexical meaning; normalized `relevance` controls ordering; whole-term matching means "deploy" no longer matches "deployment". `messageLimit` defaults to 3 (maximum 10; 0 disables messages; a negative or non-numeric value means 3): raw HTTP callers previously passing `limit` above 3 could receive up to 10 messages and now receive 3 plus the additive `messageMatchesAvailable` lower bound. The additive `messageScan` is `{cap, exhausted}`, plus `examined` (the number of distinct visible rows in the whole window) only when the scan finished; each lane scans up to 1,000 visible rows (`cap` is per lane) and reads at most 1,500 raw rows, and the lanes run one after the other (the text index first, in relevance order, then the recent window only if the text index did not fill the page; the first `messageLimit` + 1 eligible messages found are ranked). The page queries behind it return a bounded projection of each row (content at the write cap, only the two project fields of the metadata, and a stub for a row whose channel or session is over 512 characters or whose turn id is over 128; such a row is never returned to any request), so the size of a returned page does not depend on rows the caller may not see. For a caller that can only add rows it can see, no count, flag or choice of message depends on rows it may not see. Known limitations, for a caller that can also write rows that are invisible to its own requests or very large documents (a peer chatting through an agent normally cannot): (1) when invisible rows in a lane's scanned prefix exceed the 500-row margin before the visible cap is reached, `exhausted` is false and the visible window is truncated, which reveals an aggregate count of rows the caller may not see (in the text lane, rows matching the caller's own query term; a caller who writes up to 1,000 rows of its own can read it exactly), and rows written to be invisible to the caller's own requests lower that margin; (2) Convex's per-query read limit still applies to every message page, as before, so a caller that stores near-1 MiB documents can make a page's read size depend on whether one invisible row sits in it. Write-side limits on message metadata and identifiers are tracked as follow-up hardening (ILL-388). (ILL-311)
- New memories whose embedding fails are retried for about 31 hours. The recovery sweep remains the tool for older rows, the per-owner report accepts `--created-after`, and the daily embedding cap log no longer includes an account id. (ILL-379)
- Both MCP servers share one generated tool contract (name, description, schema, route, and trimmer), compiled into each package so the npm server still installs from the registry on its own. Recall memory content is cut at 600 characters and marked `truncated` only when it is cut; the memory, message and asset excerpts that recall, recent and message search cut are cut by code point and never inside a surrogate pair. The hosted server also resolves a knowledge base by name, as the stdio server does, and accepts a `tools/call` without `arguments` for every tool that needs none. `crystal_remember` returns `relatedExisting`: up to three active same-scope memories, from the same project, at or above the recall engine's strong lexical threshold. (ILL-313)
- Parity checks now run each query's bounded hydration batches concurrently, speeding up cutover verification while preserving result order and the per-transaction read limit. (ILL-346)
- Operators can now report and recover active memories left unsearchable after a failed embedding, with bounded spending and safe repeat runs. (ILL-366)
- Operators can scope memory recovery to selected accounts, and the sweep skips accounts without a personal key before attempting an embedding. (ILL-377)
- Harden archive privacy checks for binary encodings and metadata junk, align e2e bootstrap fixtures with the versioned contract, and add hygiene regression coverage. Historical 0.8.x archive metadata is warning-only; 0.9.x and newer reject it. (ILL-364)
- The device-authorization page no longer looks a user code up before you sign in. The unauthenticated `getSessionByUserCode` query, which let anyone probe whether a code exists, is removed; `authorizeSession` (signed-in and rate-limited per user) is now the only way to check a code, and the page reports not-found, expired and already-authorized codes from its result. (ILL-368)
- The local-backend Docker installer no longer exits silently when no controlling terminal is available to prompt for provider keys. Versions 0.9.0 and 0.9.1 are affected; run those versions from a terminal or export the provider keys they prompt for. (ILL-369)
- Operators get a backend storage GC tool (`scripts/ops/backend-storage-gc.mjs`) that reports, quarantines, purges and restores unreferenced search segments on the self-hosted backend volume, and reports export blobs and dead temp dirs. Every mutation runs the full integrity gates first (per-index coverage, live-key floor, referenced-byte drop, high eligible ratio, inventory and query success); recovery metadata is synced before any move, and quarantine, restore and purge are resumable per file, with an atomic no-clobber restore, pinned directory identities, fail-closed process inspection, a qualified stdin transport and private full inventories. The patched backend build context now clears the persistent temp dir at container start, and the publish workflow tags candidates by build-input hash and verifies the pushed image by digest. (ILL-347)

- Self-hosted first boot now stops retrying one hour after its first attempt when the bootstrap endpoint stays unavailable. After re-issuing a bootstrap token, run `local/bootstrap:_resetForNewToken` on the local backend to retry. (ILL-327)

- Invalid or expired device codes now count toward the device-authorization rate limit. (ILL-326)

- Onboarding finalizes failed signup attempts when verification throws, reports the longest wait across exceeded quotas, and shows the existing not-configured message when the verification secret is missing. (ILL-363)

- Local-installer API-key revocation is enforced across REST and the MCP gateway at auth time, including dashboard revoke, regenerate and delete, and previously revoked rows. Public local-key functions refuse on hosted deployments, and every self-hosted compose healthcheck probes IPv4 loopback. (ILL-361)

- Research durable findings (`POST /api/research/memory`) are stored again; their embedding is computed in the background like other new memories. (ILL-357)

- Several operator and admin paths no longer fail with Convex's "multiple paginated queries" error. The operator scope report now moves from memories to messages on a separate call. The dashboard-totals rebuild, the weekly stats drift check and the backlog-depth probe now page through the database one call at a time. The admin email log's status filter pages instead of looping, so a filtered page can hold fewer entries than the limit; use Load More for the rest. Low-salience review reads one bounded batch. `backfillDashboardTotalsForUser` and `computeAndStoreSourceOfTruth` are now internal actions: run them with `convex run` as before. `getBacklogDepth` now returns one page per call, with a cursor. (ILL-358)

- The production deploy gates (known-source recall smoke, lifecycle API smoke, and a recall probe with a numeric regression mode) now live in the repository under `scripts/ops/deploy-gates/`, with every production fixture in a private file outside git. Hosted operations tooling under `scripts/ops/` is excluded from the public mirror and the local-backend artifact. (ILL-351)

- Update, edit and supersede refuse writes that would replace a stored secret with a redaction placeholder in title, content, metadata, tags or action triggers (409 `redacted_content_write`; override with `allowRedactedContent: true`). Agent reads redact secret-shaped tags and triggers. The rule is field-precise: a field is refused only when the incoming value carries a placeholder and the stored field is lossy on read, so placeholder text on a memory without secrets is accepted. All three MCP clients (`mcp-server`, the hosted server and the OpenClaw plugin) expose and forward `allowRedactedContent` only when true, and a machine-readable HTTP route inventory now lists every route with whether it returns memory text, checked by a drift test against the router. (ILL-360)

- `dedupeText` is no longer returned by any HTTP route; it was an internal key and carried unredacted content. Agent-facing reads now redact secret-shaped text and flag it. Recall, memory get, triggers, trace (including the source conversation messages), wake (recent memories and the briefing), checkpoint lists, asset metadata and the knowledge-base item, listing and query routes all redact; a changed memory carries `redacted: true` and `redactedFields`, and `metadata` stays valid JSON. Update and edit refuse a new title or content containing a redaction placeholder with 409 `redacted_content_write` unless the body sets `allowRedactedContent: true`. The `GET /api/memories` export stays raw by design. (ILL-328, ILL-330)

- Self-hosted first boot shares one versioned payload contract with the cloud bootstrap endpoint; a failed first-boot delivery can be retried for 10 minutes; a spent token now stops retrying and points to recovery. (ILL-323)

- Checkout now requires a signed-in account and links the subscription to it; payments that can't be applied are recorded for reconciliation instead of dropped. (ILL-321)

- Memory get, edit, update, supersede, trace and forget now enforce channel and knowledge-base visibility for unscoped requests, matching recall: an unscoped request reaches only channel-less non-KB memories, and KB chunks are gated by the KB's agent allow-list. Pass the memory's channel (or `scopeChannel` on edit, update and supersede, which scopes visibility without re-homing the memory) and your `agentId` to act on scoped or KB memories. The KB enumerate response now includes each chunk's `channel`. (ILL-319)

- Cloud provisioning quotas are now per account and per verified email domain; the verification challenge is required on cloud deployments. Operators must set both Turnstile keys (`TURNSTILE_SECRET_KEY` on cloud Convex, `NEXT_PUBLIC_TURNSTILE_SITE_KEY` on the web app) before enabling cloud onboarding.

- Unscoped message search and recent messages, wake (its recent block and its last-session block), `crystal_trace` snapshots and the message-derived counters of `reflect` no longer expose private peer or group conversations. **The `crystal_recall` message lane is not changed by this release:** an unscoped recall can still return messages from private channels; pass a `channel` to scope it. A later release changes the recall lane. Message search and recent requests carrying a `channel` or `sessionKey` are unchanged. Three exceptions: wake reads one channel only (pass `channel`; a `sessionKey` alone does not scope it); `crystal_trace` shows a private snapshot only to a request that names that snapshot's channel; `reflect` returns its counters only when the request carries a `sessionKey`. With the default empty allowlist, every bare-label channel is treated as private for unscoped requests; set `RECALL_WORK_CHANNEL_LABELS` (comma separated) in the local Convex environment to keep chosen labels visible. (ILL-320)

- Impersonation now re-checks the actor's current manager/admin role on every request. Role changes that remove support access end that user's support sessions and deactivate API keys they created or regenerated for other accounts.

- Research-scoped API keys now receive 401 on non-research endpoints; stacks that cannot update should revoke scoped handoff keys rather than regenerate them, and after updating operators should run the scoped-key exposure summary with `--allow-local`.

- Research keys bound to a collection, workspace, agent or channel now write findings into their bound channel (or the collection's), and can promote only into the collection's own promotion knowledge base.

- The self-hosted MCP container now receives its backend URL and exposes an unauthenticated /healthz liveness probe.

## 0.9.3 — 2026-10-01

### Fixed — Local backend

- Local installers now default to the reproducible, privacy-scrubbed 0.9.3 tar.gz and zip archives. Upgrades from 0.9.0, 0.9.1 and 0.9.2 keep the existing local identity and data.
- Unscoped message search and recent messages, wake (its recent block and its last-session block), `crystal_trace` snapshots and the message-derived counters of `reflect` no longer expose private peer or group conversations. **The `crystal_recall` message lane is not changed by this release:** an unscoped recall can still return messages from private channels; pass a `channel` to scope it. Three exceptions: wake reads one channel only (pass `channel`; a `sessionKey` alone does not scope it); `crystal_trace` shows a private snapshot only to a request that names that snapshot's channel; `reflect` returns its counters only when the request carries a `sessionKey` (a `channel` alone no longer does).

### Release scope

- This release updates only the local-backend artifact and universal installer defaults. Plugin, MCP-server and OpenClaw package pins remain unchanged; the shared MCP health runtime version remains `0.9.0` because it does not identify this archive release.
- `convex/schema.ts` is unchanged since 0.9.2. Nothing in the shipped delta is incompatible with 0.9.2, 0.9.1 or 0.9.0 data.
- CI smoke and typechecks the explicit 0.9.0, 0.9.1, 0.9.2 and 0.9.3 archive set, and runs the packaged privacy regression on 0.9.3. The no-Docker upgrade matrix covers 0.9.2, 0.9.1 and 0.9.0 to 0.9.3. The Docker canary upgrades 0.9.1 to 0.9.3 while checking identity and memory recall.

## 0.9.1 — 2026-09-29

### Fixed — Local backend

- Local installers now default to the reproducible, privacy-scrubbed 0.9.1 tar.gz and zip archives. Upgrades from 0.9.0 preserve the existing local identity and stage the new backend alongside the previous version.
- Agent-facing memory, knowledge-base, checkpoint, trace and asset reads redact secret-shaped text. Internal deduplication text stays out of HTTP responses; title and content edits containing redaction placeholders require explicit opt-in. Raw memory export remains unchanged. (ILL-328, ILL-330; A08)
- Research writes enforce bound channel and promotion knowledge-base restrictions, and durable findings are stored with deferred embedding again. (ILL-333, ILL-357)
- First boot consumes the shared versioned bootstrap contract, handles spent tokens, and limits retries to one hour from the first attempt. Existing bootstrap records remain valid through an optional schema field. (ILL-323, ILL-327; A13, A07)
- Asset uploads read the request body once; vector side-row repair preserves its page cursor after deleting stale rows. (ILL-344, ILL-345)
- Scope reports, dashboard totals, stats drift checks, backlog probes, email-log filtering and low-salience review use bounded pagination. Invalid or expired device codes count toward authorization rate limits. (ILL-358, ILL-326)

### Release scope

- The already-shipped memory-by-id visibility protection from 0.9.0 remains in place.
- The full redacted-write guard (metadata, tags and action triggers, and supersede; ILL-360) and self-hosted API-key revocation parity (ILL-361) ship in 0.9.2.
- This is a local-backend artifact release. Plugin, MCP-server, OpenClaw package pins and the shared runtime health version remain at their existing versions.
- CI checks both 0.9.0 and 0.9.1 archive formats and runs the 0.9.0 to 0.9.1 upgrade without Docker. The Docker-mode upgrade canary was not run: its first CI attempt found the 0.9.0 installer exiting silently in Docker mode (ILL-369).
- Prefer a forward fix in 0.9.2. Reverting the default to 0.9.0 requires confirming compatibility with 0.9.0 code and an advisory telling 0.9.1 users not to re-run the installer until fixed.
- The vector cutover parity gate (`verifyTopKParity`, `verifyTopKParitySample`) no longer requires identical ordered top-K IDs. It over-fetches both indexes, reports every hydration drop with a reason, rescores the union exactly with the side vectors, requires byte-identical inline and side vectors, and classifies each query as `exact_match`, `tie_equivalent`, `side_better_or_equal`, `side_worse` or `coverage_gap`. Any coverage gap fails hard; otherwise the side index must match the inline index's recall and exact cosine within provisional documented tolerances. Amendment v2.1 uses per-list self budgets and capped boundary credit, rejects empty unions and self hits missing from both lists, and hydrates in action-driven batches capped at 12 MiB per transaction. The old strict counts remain informational; the cutover driver requires complete evidence and independently recomputes every quality threshold. (ILL-346)

## 0.9.0 — 2026-09-07

### Changed — Lean durable memory

- Completed turns now persist once idempotently without running per-turn inference. Durable extraction remains a bounded, demand-driven background operation.
- Default recall is deterministic and bounded. It searches durable long-term memory and recent unextracted messages while optional knowledge bases, assets, and research remain explicit.
- Long-term memory is converging on one authoritative vector table and index through a phased, fail-closed migration with count audits and rollback checkpoints.

### Fixed — Cross-client recall isolation (P0 confidentiality)

- **Multi-client accounts (e.g. a coaching operator with one peer channel per client) could recall another client's private data.** Two independent gaps are now closed. (1) Non-KB memories written under a **bare peer-capable scope** (a peer-capable agent prefix with no `:<peerId>` suffix) prefix-matched every peer; a broad or absent peer-scoped recall now **fails closed** (returns nothing) instead of surfacing all peers. Channel-less chunks (shared training corpora such as books, courses, and podcasts) are unaffected.
- Verified with a filter-replay simulation across multiple peers on a live multi-client account: **zero** cross-peer memories and **zero** cross-peer KB chunks surface for a peer-scoped request, while each peer still recalls its own content.

Responses now include `pagination` (`hasMore`, `nextOffset`) and the resolved `window`, so an agent can answer "what did X say last month about Y" and page the complete set instead of asserting a window is empty from a single relevance-capped page.

## Deployment Notes

> **Production backend:** Memory Crystal production Convex is self-hosted on Railway at `https://convex.memorycrystal.ai`, not Convex Cloud. Use the production deployment wrappers.

To deploy to production:

```bash
# Deploy Convex backend (schema + functions)
npm run convex:deploy

# Or for local dev:
npx convex dev

# MCP server (if running standalone):
cd mcp-server && npm run build && npm start
```

**Environment variables required:**
- `GEMINI_API_KEY` — required for embeddings and graph enrichment (Gemini-native since v0.7.5)
- `CONVEX_URL` — Convex deployment URL (production: `https://convex.memorycrystal.ai`, set in mcp-server `.env`)
- `GEMINI_DAILY_CALL_CAP` — optional daily Gemini API call limit (off by default, added in v0.7.6)
